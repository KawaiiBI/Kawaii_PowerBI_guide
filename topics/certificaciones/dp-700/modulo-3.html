2. ¿Qué es Apache Spark?

Procesamiento distribuido

Apache Spark es un framework de procesamiento distribuido open-source. Cuando tienes muchísimos datos que no caben en una sola máquina, Spark distribuye el trabajo entre varios nodos y coordina la ejecución. En Fabric, ese conjunto de máquinas es un Spark pool.

Lenguajes: PySpark (el más popular), Spark SQL, Scala, SparkR y Java. En la práctica, PySpark y Spark SQL cubren el 95%.

El punto de entrada a todo es el objeto spark (una SparkSession), ya creado automáticamente en cada notebook.

🏗️

3. Arquitectura: driver, workers, executors

Los tres tipos de procesos

  • Driver (uno): vive en el head node, es el cerebro que planifica y coordina. Contiene la SparkSession. Si se cae, la sesión entera se cae.
  • Workers (varios): las máquinas que hacen el trabajo real. Cada worker es un nodo.
  • Executors: los procesos que ejecutan tareas dentro de cada worker, en paralelo.
🎯 Detalle de Fabric: la ratio nodos a executors es siempre 1:1. Con N nodos, uno se reserva para el driver y los demás son executors. En single-node, driver y executor comparten recursos.
🌊

4. Spark pools en Fabric

Starter pool vs Custom pool

Starter pool: se crea automáticamente en cada workspace, está pre-hidratado (live), arranca en segundos. Ideal para desarrollo. Config limitada (medium) y sin private link.

Custom pool: lo defines tú con node size, autoscale, dynamic allocation y private endpoint. Sin live mode tarda ~3 min en arrancar; los custom live pools arrancan en ~5 seg.

⚠️ Prerequisitos para custom pools: rol Admin en el workspace y que un capacity admin haya habilitado "Customized workspace pools". Sin eso, solo starter pool.

Ruta: Workspace settings → Data Engineering/Science → Spark settings.

7. Environments

Un perfil reutilizable de runtime + librerías + config

Un environment es un item que empaqueta un runtime, las librerías instaladas, configuración Spark, ficheros de recursos y un pool asignado. Se puede marcar como default del workspace y anular a nivel notebook.

Para una librería puntual en la sesión (no persistente):

%pip install pandas==2.1.3
%conda install seaborn=0.13.0
⚠️ La instalación en línea con %pip/%conda solo dura la sesión. Para persistencia, usa un environment.
⚡

8. Optimizaciones exclusivas de Fabric

Muy examinables

  • 🎯 Native Execution Engine (NEE): motor vectorizado, mejor rendimiento sobre Parquet/Delta. NO está activado por defecto, hay que activarlo.
  • 🎯 High Concurrency Mode: comparte una sesión Spark entre notebooks/usuarios (mismo lakehouse, environment y config). Reduce startup. Hay que activarlo en workspace settings.
  • 🎯 V-Order: optimización de escritura Parquet, activada por defecto.
  • Adaptive Query Execution (AQE): activada por defecto; ajusta shuffle partitions, joins y skew.
  • Autotune: solo Runtime 1.2 (retirado).
%%configure
{
    "conf": {
        "spark.native.enabled": "true",
        "spark.shuffle.manager": "org.apache.spark.shuffle.sort.ColumnarShuffleManager"
    }
}
⚠️ %%configure tiene que ser la primera celda del notebook para que aplique.
📝

9. Notebooks vs Spark Job Definitions

Dos formas de ejecutar código Spark

Notebook: interactivo, cell-by-cell, resultados inline, ideal para exploración, desarrollo y ML.

Spark Job Definition (SJD): ejecuta un script Python/JAR no interactivo, on-demand o por schedule, ideal para producción y ETL automatizado.

🎯 Regla: exploración/ML → Notebook. ETL programado en producción → SJD. Ojo: los notebooks también se orquestan desde pipelines (actividad Notebook), muy común en Fabric.
✨

11. NotebookUtils (antes MSSparkUtils)

Librería built-in para tareas comunes

Maneja file system, environment variables, encadenado de notebooks, secrets y credentials. En 2024 se renombró de mssparkutils a notebookutils (el antiguo sigue funcionando por compatibilidad).

import notebookutils

# File system
files = notebookutils.fs.ls("Files/my_folder")
notebookutils.fs.cp("Files/source.csv", "Files/backup/source.csv")

# Encadenar notebooks
result = notebookutils.notebook.run("path/to/other_notebook", timeout_seconds=60, args={"p": "v"})

# Salir con valor
notebookutils.notebook.exit("Success: 1000 rows")

# Secret de Key Vault
secret = notebookutils.credentials.getSecret("kv-name", "secret-name")
🎯 notebookutils.notebook.runMultiple() ejecuta notebooks con dependencias tipo DAG. Ideal para orquestar medallion (bronze → silver → gold).
📊

12. Trabajar con DataFrames

El corazón de PySpark

Un DataFrame es una tabla distribuida con filas y columnas, inmutable. Cargar datos con schema inferido o explícito (el explícito mejora el rendimiento):

from pyspark.sql.types import StructType, StructField, IntegerType, StringType, FloatType

schema = StructType([
    StructField("ProductID", IntegerType()),
    StructField("ProductName", StringType()),
    StructField("Category", StringType()),
    StructField("ListPrice", FloatType())
])
df = spark.read.load('Files/data/product-data.csv', format='csv', schema=schema, header=False)
display(df.limit(10))

Operaciones típicas (method chaining)

from pyspark.sql.functions import col, count, avg

result = (df.select("ProductName", "Category", "ListPrice")
            .where(col("Category").isin("Mountain Bikes", "Road Bikes"))
            .orderBy("ListPrice", ascending=False)
            .limit(20))

stats = df.groupBy("Category").agg(
    count("ProductID").alias("num_products"),
    avg("ListPrice").alias("avg_price"))

Guardar

# Delta gestionada (aparece en el catálogo)
df.write.format("delta").saveAsTable("mi_tabla_delta")
# Parquet a una ruta
df.write.mode("overwrite").parquet('Files/product_data/bikes.parquet')

Modos de escritura: overwrite, append, ignore, error (default).

📁

13. Particionado de datos

Dividir el output en subcarpetas por columna

sales_df.write.partitionBy("year", "month").mode("overwrite").parquet("Files/sales_data")

Beneficios: predicate pushdown (Spark lee solo las particiones relevantes), paralelismo y mejor compresión.

⚠️ NO particiones por columnas de alta cardinalidad (user_id, order_id, timestamp): generas miles de ficheros minúsculos y va peor. Usa columnas de baja cardinalidad (year, country, category). Regla: ~1 GB por partición.
🎯 Trampa: al leer directamente una partición (.../Category=Road Bikes), la columna particionada desaparece del DataFrame.
🗂️

14. Spark SQL: catalog, views y tablas

El catalog y las vistas

El Spark catalog registra databases, tables, views y functions. Una temporary view existe solo durante la sesión y hace queriable un DataFrame con SQL:

df.createOrReplaceTempView("products_view")
result = spark.sql("SELECT * FROM products_view WHERE Category = 'Bikes'")
⚠️ Trampa: %%sql en un notebook corre en el Spark SQL engine del pool, NO en el SQL analytics endpoint. Son motores distintos.
🎯 Usa spark.sql() cuando quieras el resultado en Python; usa %%sql cuando solo quieras ver el resultado. Delta es el formato preferido (otros no aparecen en el SQL endpoint).
📈

15. Visualización en notebooks

Charts built-in, Matplotlib y Seaborn

Los resultados se pueden ver como chart desde la UI (rápido pero limitado). Para gráficos ricos, Matplotlib y Seaborn necesitan datos en Pandas.

from matplotlib import pyplot as plt
# 1) Agregar con Spark (distribuido)  2) toPandas() del resultado  3) graficar
data = spark.sql("SELECT Category, COUNT(ProductID) AS n FROM products GROUP BY Category").toPandas()
plt.bar(x=data['Category'], height=data['n'], color='orange')
plt.show()
⚠️ .toPandas() trae todos los datos al driver. Con datasets grandes → out of memory. Úsalo solo tras agregar.
🎛️

17. Trampas típicas

  • "Pool = environment" → ❌ el pool es el compute; el environment es la config (runtime, libs, props).
  • "Autoscale = dynamic allocation" → ❌ autoscale escala nodos, dynamic allocation escala executors.
  • "El custom pool arranca al instante" → ❌ ~3 min (salvo custom live ~5 seg). El starter sí en segundos.
  • "Native Execution Engine está por defecto" → ❌ hay que activarlo con %%configure o environment.
  • "En Fabric hay Spark 3.4" → ❌ mínimo Spark 3.5 (Runtime 1.3) o 4.1 (Runtime 2.0).
  • "%%sql corre en el SQL analytics endpoint" → ❌ corre en el Spark SQL engine.
  • ".toPandas() es siempre seguro" → ❌ trae todo al driver, riesgo de OOM.
  • "Todos los magics funcionan en pipelines" → ❌ solo pyspark/spark/csharp/sql/configure.
  • "High concurrency mode está por defecto" → ❌ hay que activarlo.
